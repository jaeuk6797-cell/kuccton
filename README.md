# SUP

하루 10초의 소리를 주고받으면 의성어 이름을 가진 꽃으로 피어나는 두 사람만의 정원.
React + Vite 웹앱을 Capacitor로 감싸 Android/iOS 앱으로 빌드합니다. 서버는 Supabase, 목소리 감정 분석은 `server/`의 Python 서버를 씁니다.

## 1. Supabase 준비 (한 번만)

1. [supabase.com](https://supabase.com)에서 프로젝트 생성
2. **SQL Editor**에서 `supabase/schema.sql` 실행
   이미 이전 버전 스키마를 실행했다면 `supabase/migrations-002.sql`, `-003`, `-004`, `-005`, `-006`, `-007`(대화), `-008`(놀러 가기는 모양만), `-009`(프로필 사진·닉네임), `-010`(정원 50송이·정리하기), `-011`(거절·정리한 소리 다시 심기)을 차례로 실행하면 됩니다.
   > ⚠️ **`migrations-009.sql`을 실행해야 나 탭에서 프로필 사진·닉네임을 바꿀 수 있습니다.** (members.avatar_url 칸, `update_profile` 함수, 공개 버킷 `avatars`, 친구 목록에 사진 추가)
   > 실행 전에 저장을 누르면 "프로필 기능이 아직 서버에 없어요 (Supabase에서 migrations-009.sql 실행 필요)"가 나옵니다.
   > ⚠️ **`migrations-006.sql`을 실행해야 친구 정원 놀러 가기가 동작합니다.** 친구 정원에는 *그 친구가 받아서 심은 소리*가 보이는데,
   > 받은 소리는 보낸 사람 정원에 저장되어 있어서 방문용 함수(`visit_flowers`)와 소리 파일 읽기 권한이 따로 필요합니다.
   > 실행 전에는 놀러 가기 화면에 "서버 준비가 아직 안 됐어요 (Supabase에서 migrations-006.sql 실행 필요)"가 나옵니다.
3. **Authentication → Sign In / Providers → Email** 켜기. 해커톤 동안은 **Confirm email을 꺼 두세요**(기본 메일 발송은 시간당 몇 통으로 제한되고, 확인 링크를 눌러야 로그인됩니다). 로그인은 필수이며 익명 로그인은 쓰지 않습니다.
4. `.env.example`을 `.env`로 복사하고 값 입력
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=sb_publishable_...
   VITE_EMOTION_API_URL=http://localhost:8000
   ```

## 2. 감정 분석 서버 (사람 목소리 꽃)

```bash
cd server
pip install -r requirements.txt     # torch, transformers 등. 처음 실행 때 모델을 내려받습니다
uvicorn server:app --host 0.0.0.0 --port 8000
```
- 브라우저 webm을 변환하려면 `ffmpeg`가 설치되어 있어야 합니다.
- 폰이나 앱에서 부르려면 https 주소가 필요합니다. 예: `ngrok http 8000` → 나온 주소를 `VITE_EMOTION_API_URL`에 입력.
- 서버가 꺼져 있으면 목소리 꽃은 감정을 직접 고르게 됩니다.

## 3. 개발 (브라우저)

```bash
npm install
npm run dev          # http://localhost:5173
npm run dev:phone    # 같은 와이파이의 폰에서 https://<PC IP>:5173
```
두 사람 테스트는 계정 두 개로, **다른 브라우저나 시크릿 창**에서 각각 로그인하세요.

## 5. 앱 직접 빌드 (Capacitor)

`.env` 값은 빌드할 때 앱에 들어가므로 먼저 채워 두세요.

- **Android** (Android Studio 필요): `npm run android` → 폰 연결 후 ▶ Run
- **iOS** (Mac + Xcode + CocoaPods): `npm run ios` → Signing에서 Team 선택 후 ▶
- 웹 코드만 바꿨다면 `npm run cap:sync`

### 실시간 수정
`capacitor.config.json`의 `server.url`이 배포 주소(https://kuccton.vercel.app)를 가리킵니다.
설치된 앱은 이 주소를 불러오므로, `main`에 푸시하면 Vercel이 다시 배포하고 앱에도 바로 반영됩니다(앱 재빌드 불필요).
인터넷 연결이 필요하니 시연장에서는 핫스팟을 준비하세요. 오프라인 빌드가 필요하면 `server` 항목을 지우고 `npm run cap:sync` 하면 됩니다.

## 6. 꽃이 피는 규칙

녹음 전에 **사람 목소리 / 다른 소리**를 고릅니다.

| | 목소리 | 다른 소리 |
|---|---|---|
| 꽃 종류 | 감정 분석 → 감정 꽃 7종 (깔깔, 콩닥콩닥, 도란도란 …) | 분류 없이 소리 특징만으로 (톡, 토독, 타닥, 살랑 …) |
| 변형 | onset 수 → 단일/기본/첩어, 크고 낮으면 음성모음, 어택 강하면 거센소리 | 리듬 × 세기 × 모음, 길게 이어지면 살랑·웅웅 |
| 꽃말 | STT 문장 | 없음 |

공통: onset 수 = 꽃잎 수(3~8), 어택 강함 = 뾰족한 꽃잎, 파형 윤곽 = 꽃잎별 길이.
같은 날 두 사람이 모두 보내면 **우리의 꽃**이 피고, 누르면 상대 소리는 왼쪽·내 소리는 오른쪽 귀로 동시에 들립니다.

자세한 구조는 [CLAUDE.md](CLAUDE.md)를 보세요.

받은 소리함에는 아직 고르지 않은 소리만 표시됩니다. ‘심기’나 ‘괜찮아요’를 누른 소리는 소리함에서 사라지고, **친구 → 해당 친구 → 주고받은 소리**에 남습니다. 내역에서 다시 듣고, ‘괜찮아요’ 했던 소리도 정원에 심을 수 있습니다. **Supabase SQL Editor에서 `supabase/migrations-011.sql` 실행이 필요합니다.** 최신 정원 50송이 제한을 유지하면서 거절·정리한 소리도 다시 심을 수 있게 합니다.

## 처음 사용 안내

처음 정원에 들어오면 소리 도착 알림 설정 → 친구 맺기 → 녹음 → 소리 심기 → 우리의 꽃 → 다시 듣기의 6단계 튜토리얼이 열립니다. 정원을 처음 만든 직후에 시작하며, 완료하거나 ‘나중에’를 누르면 닫힙니다. 도움말 아래 ‘튜토리얼 다시 하기’에서 다시 볼 수 있습니다. 도움말에는 앱 취지만 남깁니다.
개발 화면 `/?view=home&friends=3&tutorial=1`에서 첫 안내를 확인할 수 있습니다.

**배포 시 SQL 실행 필요:** 신규·기존 프로젝트 모두 `schema.sql` 또는 기존 마이그레이션 적용 후 `supabase/migrations-011.sql`을 실행해 주세요. 튜토리얼에는 별도 DB 변경이 없습니다.

## 앨범·녹음 음량 변경

- 앨범에는 처리 상태와 관계없이 받은 소리와 우리의 꽃이 모입니다. 받은 소리 상세에서 정원에 심기·빼기, 내 앨범에서 삭제를 선택합니다. 삭제는 수신 항목만 제거하며 보낸 사람의 원본 꽃·소리 파일은 유지합니다.
- **Supabase SQL Editor에서 `supabase/migrations-012.sql` 실행이 필요합니다.** `migrations-011.sql` 다음에 실행해 수신자 본인 항목의 삭제를 허용합니다.
- 새로 공유하는 녹음은 분석 후, 전송 전에 작은 음량만 보정합니다(최대 8배, 피크 0.95 제한). 모양·감정 분석에는 원본을 사용합니다. 보정한 파일은 PCM WAV로 저장되며 기존 파일은 변경하지 않습니다.
- 하단 ‘오늘의 위로’·‘오늘의 소리 10초’ 버튼은 항상 표시하며 접기·펼치기는 사용하지 않습니다.
- 개발 미리보기 `/?view=home&friends=3&many=50&inbox=12`는 50개가 찬 정원에서 51번째 심기 시 2초 중앙 알림과 앨범 정리를 확인하는 용도입니다.

- 앨범·친구 화면은 SUP·제목·메뉴를 고정하고 목록과 내역만 스크롤합니다. 우리의 꽃은 상대 소리를 왼쪽 채널에만, 내 소리를 오른쪽 채널에만 재생합니다.

## 소리 도착 푸시 알림 (웹을 닫아도 수신)

나 탭에서 기기별로 ‘소리 도착 알림’을 켜고 끌 수 있습니다. 갤럭시의 지원되는 Chrome·삼성 인터넷, iPhone/iPad의 홈 화면 웹앱(iOS/iPadOS 16.4 이상)에서 시스템 알림을 허용해야 합니다. 알림을 누르면 받은 소리함이 열립니다. 로그아웃하면 해당 기기 구독을 해제합니다.

**서버 적용 필요:** Supabase SQL Editor에서 `supabase/migrations-013.sql` 실행, `sound-push` Edge Function 배포, VAPID·웹훅 키와 Vault 설정이 모두 필요합니다. 웹사이트 배포만으로는 발송되지 않습니다. 관리 권한이 있는 팀원은 **[푸시 서버 적용 안내](supabase/PUSH_SETUP.md)**를 따라 주세요. 키는 프런트엔드나 GitHub에 넣지 않으며, `.env`와 `package-lock.json`은 변경하지 않습니다.

## 소리 재생 UI

모든 소리 재생기는 재생·일시정지 버튼과 시간만 표시합니다. 음량·배속·다운로드 메뉴는 노출하지 않습니다. 우리의 꽃은 두 녹음을 하나의 2채널 WAV로 준비해 일반 미디어 재생으로 함께 듣습니다. 왼쪽에는 상대 소리, 오른쪽에는 내 소리만 들어가고 짧은 쪽의 남은 구간은 무음입니다. iOS에서 재생용 AudioContext 상태에 의존하지 않으며, 준비 실패 시 다시 시도 버튼을 보여 줍니다. 실기기 두 계정 재생 검증은 별도로 필요합니다.

## 대량 데이터 화면 데모 (개발 서버 전용)

`npm run dev` 후 `/?view=home&friends=100&many=50&album=1000&tab=album`에서 친구 100명·받은 소리 1,000개(우리의 꽃 별도)·정원 50개를 확인합니다. `tab=friends`는 친구 목록, `tab=garden`은 정원으로 바로 엽니다. `friends`는 최대 200명, `album`은 최대 5,000개까지 생성하며 정원은 항상 50개 이하입니다. 실제 DB나 계정에는 쓰지 않고, 이 데모는 배포 빌드에서 사용할 수 없습니다.

## 앨범 정리와 친구 제한

- 앨범은 한 줄 5개로 표시하고 상단에서 연도·월을 선택합니다. 기본은 가장 최근 연월이며 ‘전체 연도’로 모든 기록을 봅니다. 기간을 바꿔도 상단 메뉴와 선택기는 유지됩니다.
- 받은 소리함은 항목 1~2개만큼 높이를 맞추고, 3개 높이에서 멈춰 4개부터 내부 스크롤합니다. 낮은 화면에서는 화면 안에 들어오는 높이가 우선입니다.
- 정원 친구 선택창의 검색은 제거했습니다. 각 친구 옆 핀으로 상단에 최대 3명을 고정하며 이 기기의 계정별로 저장됩니다.
- **친구 등록은 최대 20명입니다. Supabase SQL Editor에서 `supabase/migrations-014.sql` 실행이 필요합니다.** 양쪽 계정의 한도를 검사하고 동시 등록을 직렬화합니다. 기존에 초과한 친구는 삭제하지 않으며 같은 친구의 재등록은 유지합니다. 푸시 알림 설정과 별개로 적용할 수 있습니다.
- 100명 데모는 기존 초과 상황을 확인하는 가짜 데이터입니다. 실제 신규 등록 한도는 20명입니다. 현재 규칙 확인용은 `/?view=home&friends=20&many=50&album=1000&inbox=4`를 사용합니다.

첫 가입 후 정원을 만들면 튜토리얼 첫 단계에서 알림을 직접 켜거나 나중에 설정하도록 선택합니다. 시스템 권한은 ‘알림 켜기’를 눌렀을 때만 요청하며, 도움말의 튜토리얼 다시 하기로도 접근합니다. 앨범 날짜 옆에는 해당 날짜에 표시되는 꽃·나무·우리의 꽃 수를 작은 숫자로만 표시합니다. 핀 개수 표시는 없고 네 번째 고정 시 2초 중앙 알림을 띄웁니다.

앨범의 연도·월은 기본 select 대신 둥근 버튼과 앱 자체 선택 목록을 사용합니다. 선택 목록은 밖을 누르거나 Esc로 닫히며 키보드 방향키로 이동할 수 있습니다.
